## 1. Overview

### 1.1 Purpose and DUT Identity

验证对象为综合顶层 `axi_interconnect`：默认配置下，3 个上游发起端和 3 个下游目标端之间的 AXI3-style 五通道交叉开关。环境覆盖地址路由、SID 编解码、AW/W/B/AR/R 透明传递、轮询仲裁、30 个边界 FIFO、两个 4-entry outstanding-ID tracker、默认 DECERR 从设备、反压、复位、并发和前向进展。

接口是 AXI3 子集而非完整 AXI3：存在 WID 和 4-bit LEN，但没有 LOCK/CACHE/PROT/QOS 等侧带属性，并依赖 `WID[3:2]` 携带目标编码这一自定义约定。

### 1.4 Verification Scope

In scope：六个外部 endpoint 的五通道；3×3 请求和真实 S0/S1/S2/default 四来源返回路径；route/SID/WID/burst；FIFO、SID tracker、仲裁/default FSM；正向、负向、CR、stress、performance measurement 和 coverage；已知 SID 提前 clear 风险。

Out of scope：缓存一致性、CSR、中断、CDC、width conversion、QoS、低功耗、ECC/parity、flush/kill；未定义的频率、绝对最大延迟和保证带宽；未暴露的完整 AXI3 属性。没有外部 DUT port 被有意悬空。

## 4. Stimulus Strategy

### 4.1 Transaction Types

| Type | Fields | Producer / consumer |
|---|---|---|
| `axi_ic_aw_item` | id, addr, len, size, burst, delay, hold, epoch | M driver; S target/monitor |
| `axi_ic_w_item` | id, data[], strb[], last, gaps, target code, error | M driver; S target/monitor |
| `axi_ic_b_item` | sid/id, resp, delay, source, error | S target; M monitor |
| `axi_ic_ar_item` | AW-like address fields | M driver; S target/monitor |
| `axi_ic_r_item` | sid/id, data[], resp[], last, delays, interleave | S target; M monitor |
| `axi_ic_chan_evt` | side, index, channel, payload, cycle, epoch | monitors; model/scoreboard/coverage |
| `axi_ic_reset_item` | assert phase, low cycles, release phase | reset controller |

Driver 将 burst item 拆成 beats；monitor 保留每次外部握手的原始 payload，assembler 依据 ID/LAST 建立 burst view。

### 4.2 Protocol Capabilities

- AW/W/AR 可独立启动；W 可早于、同拍或晚于 AW 0–8 cycles。
- 每通道支持 valid-before-ready、ready-before-valid、同拍、back-to-back 和 1-cycle gap。
- LEN 0..15、SIZE 0..7、BURST 0..3、ID 0..15、全部 WSTRB 和重点 data patterns。
- Target responder 支持 B/R delay、跨 SID reorder、R beat interleave、RESP/data 注入。
- READY stall 支持 0、1、2–5、6–15、16+ cycles 与随机波形。
- Outstanding 1..4；pipeline sequence 可在上一 transaction 未完成时发送下一笔。
- 独立负测 item 支持 unknown SID、spurious B、WID target mismatch、early/missing LAST、ID mismatch、VALID early drop 和 illegal-state force。

### 4.3 Sequence Library

- `axi_ic_route_vseq`：3×3 matrix、地址边界、default holes。
- `axi_ic_read_vseq` / `axi_ic_write_vseq`：single、burst、outstanding、interleave。
- `axi_ic_arb_vseq`：2/3-way M contention 和 2/3/4-source response contention。
- `axi_ic_fifo_pressure_vseq`：fill/drain、empty/full simultaneous operations。
- `axi_ic_sid_vseq`：occupancy、slot membership、priority、duplicates、full/release。
- `axi_ic_backpressure_vseq`：所有通道 stall 和 grant lock。
- `axi_ic_reset_vseq`：idle/active/random-phase reset 和 epoch barrier。
- `axi_ic_error_vseq`：除 error-under-load 外，每次只允许一种 expected error。
- `axi_ic_perf_vseq`：preheat、measurement window 和统计 barrier。

### 4.4 Random Scale and Runtime Control

每个 random test 使用 testplan §3 的 base count 乘统一 plusarg `+RANDOM_SCALE=N`。默认 1；0.1 用于 quick smoke；10 用于深度 closure。结果向上取整且至少 1。`+MAX_TRANSACTIONS` 是显式 override，日志必须打印最终 count。

### 4.5 Virtual Coordination and Response Handling

`axi_ic_vsqr` 持有六个 sequencer。正常流程：配置 target responder → responder-ready barrier → master traffic → 等待 child sequence → scoreboard drain → drop objection。需要同拍竞争时，由 clock-aligned barrier 同时释放 child sequences。

AW/W/AR master 与 reactive target driver 使用 non-blocking `use_response_handler`，允许多个事务在途；依赖 response 决定下一步的 polling/diagnostic sequence 使用 blocking `get_response`。Reset 时 driver 终止 pin-level transfer，返回 `UVM_NOT_OK`，epoch logic 禁止旧 response 污染新事务。

## 5. Checking Strategy

### 5.1 Granularity

| Area | Granularity | Rule |
|---|---|---|
| route/data/ID/burst | transaction/beat | full payload; no invented fixed latency |
| ready/valid hold | cycle protocol | every clock edge |
| registered eligibility | cycle internal | sample N, compare grant N+1 |
| FSM/grant lock | cycle internal | legal arc and WAIT stability |
| fairness | handshake window | 3-way/3 handshakes; 4-way/4 handshakes |
| progress | TB observation bound | next progress within 32 cycles after finite stall release |
| performance | measurement | min/avg/max, bubbles, beats/cycle |

### 5.2 Independent Reference Algorithms

1. Route 只比较 accepted AW/AR address 与三个 4 KiB窗口；0 hit 为 default，超过 1 hit 为配置错误。
2. SID=`{target_code,master_code,original_id}`，target/master code 均为 `01/10/11`。
3. M-side AW/AR 产生 pending downstream expectation；default 请求进入内部 default model，不期待真实 S event。
4. M-side W 由 `WID[3:2]` 选目标，并必须命中 accepted-AW shadow entry，才产生 expected S W beat。
5. S-side B/R 按 SID.MID 产生 expected M event；真实 R 必须命中 AR shadow entry。
6. Default read 产生 `LEN+1` 个 all-ones/DECERR beats，末拍 LAST；default write 消费规定 W beats 后产生一个 DECERR B。
7. 正常模型只在真实 `VALID&&READY&&LAST` 时释放 shadow SID，使当前 RTL 提前-clear 缺陷显性化。
8. Reset 开启新 epoch 并清空 pending state；任何旧 epoch 输出失败。

### 5.3 Scoreboard Connectivity

| FIFO | Type | Source / use |
|---|---|---|
| `m_actual_fifo[0:2]` | `axi_ic_chan_evt` | M monitor；输入给 model，B/R 给 scoreboard |
| `s_actual_fifo[0:2]` | `axi_ic_chan_evt` | S monitor；B/R 给 model，AW/W/AR 给 scoreboard |
| `m_expected_fifo[0:2]` | `axi_ic_chan_evt` | model expected B/R |
| `s_expected_fifo[0:2]` | `axi_ic_chan_evt` | model expected AW/W/AR |

每个被监测 endpoint 有一个 actual FIFO；每个输出 endpoint 有一个 expected FIFO。Monitor analysis port fanout 到 model、scoreboard 和 coverage。

### 5.4 Matching and Ordering

- 同 endpoint/channel/SID 的 beats head-of-queue 比较 data/RESP/LAST。
- 不同 ID/SID 可乱序，associative queues 用 endpoint、channel、SID、epoch 匹配。
- 多 M 争用同一 S 时不预测 winner cycle；实际输出必须匹配 pending multiset 中唯一合法项。相同 payload 重复项用 acceptance occurrence queue 消歧。
- B/R 按 MID 路由，外部 ID 必须为 SID 低 4 位；R beat index/LAST 按 SID 独立维护。
- 同 ID 多 outstanding 若外部字段不能唯一标识 occurrence，则按接受顺序比较并报告 TOVERIFY annotation，不能忽略 mismatch。

### 5.5 Protocol/Internal Checks

Scoreboard 之外独立实现：五通道 stable、decode onehot、grant onehot0、FIFO/SID occupancy、registered membership、legal states、default response count、W/R/B request association 和 clear-on-handshake。30 个 FIFO 与两个 SID tables 分别有 check instance。

| Checker ID | Required behavior |
|---|---|
| `p_aw_stable/p_w_stable/p_b_stable/p_ar_stable/p_r_stable` | `VALID&&!READY` 时 VALID 和全部 payload 稳定 |
| `p_decode_onehot` | AW/AR 至多命中 S0/S1/S2/default 之一 |
| `p_grant_onehot0` | 所有 M→S/S→M grants one-hot-or-zero |
| `p_w_matches_aw` | W SID/target 对应已接受 AW |
| `p_r_has_request` | R SID 对应已接受 AR |
| `p_b_has_request` | B SID 对应已接受 write request |
| `p_fifo_occupancy_range` | 30 个 FIFO occupancy 均在 0..4，无 overflow/underflow |
| `p_sid_occupancy_range` | AR/AW tracker occupancy 在 0..4，合法 SID 非零 |
| `p_order_grant_membership` | N+1 拍 grant 等于 N 拍 candidate SID membership |
| `p_sid_clear_on_handshake` | 只在完整 `VALID&&READY&&LAST` 后释放 SID |
| `p_legal_state` | arbiter/default FSM 只取规定编码 |
| `p_default_response_count` | default read 为 LEN+1 个 R，default write 每 AW 一个 B |

所有动态 assertions 在 reset assertion/epoch transition 时 disable，并有单独的非 vacuous positive hit counter。

当前 RTL 没有 DUT-side assertions，这是明确 gap；bind SVA 只能提供独立 TB 检查，不能宣称为设计 layer-1 protection。

### 5.6 Reporting and Pass/Fail

- UVM components 只用 `uvm_error/uvm_fatal`，不用 `$display`。
- 首个 mismatch 输出 endpoint/channel/ID/beat/epoch、expected/actual 和最近 16 events；20 个 mismatch 后 fatal。
- 正向通过：0 unexpected assertion、0 mismatch、0 valid-payload X、0 timeout、全部 queues drained、0 UVM errors/fatals。
- 负测预先登记 checker ID 和精确 count/range；只有该 violation 可记 expected。漏报或其他违例都失败。
- `tp_sid_clear_backpressure` 在当前基线要求 `p_sid_clear_on_handshake` 至少命中一次；修复基线切换为 0-failure mode。
- F24 的 RTL `$display` 由 post-run log checker 检查；其他测试出现同字符串失败。

### 5.7 Explicit Non-Checks

不检查不存在的 sideband/CSR/CDC/power/ECC；由静态 scope audit 证明。不检查绝对频率、固定端到端 latency 或未定义最大带宽。不要求非默认参数功能通过，只要求负测正确揭示风险。

#### 7.1.1 Bin Expansion Rules

- Endpoint bins：M0/M1/M2；S0/S1/S2；涉及返回源时另含 SD(default)。
- Address bins：每窗口 first/mid/last、窗口间 gaps、最低窗口以下和最高窗口以上；分别与 AW/AR cross。
- ID bins：original ID 0..15 全值；SID cross 为 3 target codes × 3 MIDs × 16 IDs。
- LEN bins：0、1、2..14、15；burst interleave 为 none/two/three；LAST position 只有最终 beat 为 legal。
- WSTRB bins：zero、single-bit、partial-multi-bit、all-one；data pattern bins 为 zero/all-one/walking-one/`0xaaaa5555`/random。
- Stall bins：0、1、2..5、6..15、16+；occupancy bins 为 FIFO/SID 的 0/1/2/3/4（需要 testplan 特指时汇总为 empty/mid/full）。
- Arbitration request masks：3-way 为 1..7，4-way 为 1..15；winner 必须属于 mask，否则 illegal。
- SID slot bins：slot0/1/2/3/miss；operation 为 push/clear/conflict；priority winner 为最低 request bit。
- Reset phase bins覆盖非边沿异步 assert phase、1/2/5-cycle low duration、idle/wait/response state 和 empty/mid/full occupancy。
- 每个非-illegal coverpoint target 为 100%；testplan 指定的高维 cross target 为 ≥90%，其余 legal crosses 为 100%。

### 7.2 Sampling and White-Box Access

- 外部 covergroup 只在 handshake event sample，避免 stalled cycles 重计事务。
- concurrency/backpressure 每 `AXI_CLK` snapshot，带 reset/epoch guard。
- FIFO/SID/FSM/grant 由 bind probe 或 `uvm_hdl_read` manifest 采样；implementation 前先运行 path-sanity test。
- Static items 由 build audit 结果导入，不伪造动态 signal hit。

### 7.3 Code and Closure Targets

| Metric | Target |
|---|---:|
| line / branch / condition | ≥95% / ≥95% / ≥90% |
| legal FSM state/transition | 100% |
| non-illegal coverpoints / crosses | 100% / ≥90% |
| assertion exercise | 100% non-vacuous or documented proof |

难覆盖区域：SID clear backpressure 用 risk test；default END/RSP chaining 用 back-to-back unmapped；FIFO empty/full exchange 用 pressure seq；全 request masks 用 barriers；混合复位用 random phase；非法 parameter/decode/state 用独立负测 SCFG。

Coverage hierarchy只计 `tb_axi_interconnect.dut` 下 RTL。排除 TB、interfaces、agents、scoreboard、behavioral responders、sim_ctrl 和第三方 UVM。每个 waiver 必须逐项说明不可达或不支持原因。

## 11. Extension Guide

### 11.1 Add a Test

1. 在匹配 feature 的 test package 新增单一 `axi_ic_<scenario>_test`。
2. 注释标记 testplan feature/row；class 只配置 knobs 和选择一个 vseq。
3. 新 stimulus capability 先添加到 `seq/`，不在 test 中 bit-bang interface。
4. 加入相应 Make list/mode，并定义 pass/fail 和 coverage intent。

### 11.2 Add Coverage

外部 transaction coverpoint 加入 `axi_ic_coverage`；内部状态加入 `axi_ic_internal_cov`。更新 traceability、sample event 和 target。新增 hierarchy path 时更新 manifest sanity test。不得从 scoreboard pass/fail 反推 coverage hit。

### 11.3 Add a BFM Knob or Error Mode

在 `axi_ic_agent_cfg` 新增带默认值字段，由 driver policy 消费，并在 base sequence 暴露 constraint。Error mode 必须有独立 enum、默认关闭、唯一 expected checker/result，且正常 constraint 明确排除。

### 11.4 Add a Checking Rule

事务语义进入 model/scoreboard；cycle/protocol/internal invariant 进入独立 checker。每条规则分配稳定 checker ID、positive non-vacuity test 和适用的单一 negative test，并接入 assertion manager。禁止全局降级 severity。

### 11.5 Implementation Readiness Gate

生成完整 tests 前，testbench 自身必须通过：六接口 loopback/monitor accounting、route model unit test、SID helper exhaustive unit test、reset epoch unit test、scoreboard deliberate-mismatch test、每条 checker vacuity test，以及 30 FIFO、2 SID tables 和全部 FSM hierarchy-path sanity。基础自测通过后，功能回归结果才可用于 DUT 签核。
