## 本次代码审查发现的设计问题（待与用户确认）

1. `rtl/axi_mtos_m3.v`：SLAVE_DEFAULT 实例的 `WSELECT` 在 `always @(*)` 的 else 分支未赋值 → 恒为 X → `WREQ` X → round-robin 比较全为 false → WGRANT=0 → **写数据永远无法到达 Default Slave**，未映射地址的写事务不会有 B 响应，且该 Master 后续 W 被 FIFO 堵塞（可能是 9-28 default 测试 3 笔只回 2 笔的根因）。Default 读通路不受影响（`sid_0_clr_rdy` 在无请求时默认为 1）。
2. W 通道按 `M_WID[3:2]` 选路由（目标 Slave 编码放在 Master 侧 ID 高位），与 AW 的地址译码没有一致性保护；Default 目标（00）无对应 WSELECT 编码。
3. R/B 返回侧 `reorder` 只做 SID 成员匹配、按 beat 重新仲裁，允许不同 Slave 的 burst 在上游 Master 端口产生 **read interleaving**；`sid_buffer` 全局共享 4 entry。
4. Default Slave 的 SID[7:6] 因 `.ADDR_BASE()` 缺省为 0 → tag = 01，与 S0 冲突（返回路由只查 [5:4]，暂不影响功能，但影响断言/参考模型校验）。
