## 1. 问题陈述

该模块在 3 个上游 AXI 发起端与 3 个下游 AXI 目标端之间提供全连接路由。它根据地址选择目标端，对同一目标的并发请求进行轮询仲裁，用扩展 ID 将返回通道送回原发起端，并对未命中地址返回 `DECERR`。**TOVERIFY：** 产品层面的吞吐、时钟频率、面积和完整 AXI3 合规目标在 RTL 中没有声明。

范围包括五个 AXI 独立通道 `AW/W/B/AR/R`、入口/出口弹性缓冲、地址译码、争用仲裁、默认错误响应和有限 outstanding-ID 跟踪。不包括缓存一致性、宽度转换、时钟域转换、QoS、区域/保护/锁/缓存属性、原子操作和低功耗控制。

## 2. 功能模型

### 2.1 端点模型

| 方向 | 数量 | 角色 | 通道 |
|---|---:|---|---|
| `M_AXI_*` | 3 | 互连作为 AXI slave，接收发起端事务 | AW, W, B, AR, R |
| `S_AXI_*` | 3 | 互连作为 AXI master，访问目标端 | AW, W, B, AR, R |

默认参数为 32 位地址、32 位数据、4 位上游 ID、8 位下游扩展 ID。每个外部端点的每条通道都有独立 ready/valid 缓冲。

### 2.2 地址路由

AW 和 AR 按高位相等关系译码：`address[31:12] == base[31:12]`。默认窗口如下。

| 目标 | 基址 | 窗口 | 地址范围 |
|---|---:|---:|---|
| S0 | `0x0000_0000` | 4 KiB | `0x0000_0000`–`0x0000_0fff` |
| S1 | `0x0000_2000` | 4 KiB | `0x0000_2000`–`0x0000_2fff` |
| S2 | `0x0000_4000` | 4 KiB | `0x0000_4000`–`0x0000_4fff` |
| 默认从设备 | 其余地址 | — | 返回 `DECERR` |

W 不带地址，目标由上游 `WID[3:2]` 译码，并同时受已接受 AW 的扩展 ID 资格约束。**TOVERIFY：** 这要求系统按 RTL 约定把目标编码放入 `WID[3:2]`；这不是从标准 AXI3 接口本身即可推导的通用约束。

### 2.3 ID 扩展与返回

正常目标收到的 8 位 ID 由 `{目标编码[1:0], 发起端编码[1:0], 原4位ID}` 组成。发起端编码固定为 M0=`01`、M1=`10`、M2=`11`；目标编码由 `ADDR_BASE[14:13] + 1` 得到，默认配置下 S0/S1/S2 分别为 `01/10/11`。B/R 返回路径读取扩展 ID 中的发起端编码并路由，外部 B/RID 截回原 4 位 ID。

### 2.4 读操作

AR 经上游 FIFO、地址译码与目标侧仲裁、下游 FIFO送出；接受 AR 时，其扩展 ID 被登记到 4 项读 outstanding 集合。R 经目标入口 FIFO进入返回交叉开关，只有 ID 存在于集合内的响应才有资格送回对应发起端。当前 RTL 在候选 `RVALID & RLAST` 时删除匹配项，未与发起端出口 FIFO 的真实 ready 握手相与；结果再经该出口 FIFO输出。

### 2.5 写操作

AW 经类似路径送出，并把扩展 ID 登记到 4 项写 outstanding 集合。W 经独立 FIFO和仲裁路径，只有其构造出的扩展 ID 命中写 outstanding 集合时才有资格转发；当前 RTL 在候选 `WVALID & WLAST` 时删除匹配项，同样未与目标出口 FIFO 的真实 ready 握手相与。B 独立按扩展 ID 返回，不受该 outstanding 集合门控。

## 3. 并发模型

- 三个发起端可并发提交事务，三个目标端可并行工作。
- 每个目标的 AW、W、AR 分别在 3 个请求者间轮询；每个发起端的 B、R 分别在 3 个真实目标加默认目标共 4 个来源间轮询。
- 仲裁 grant 在下游反压期间保持；完成一次 beat 握手后可重新仲裁。R/W grant 不锁定整个 burst，因此不同 ID 的 beat 可在 burst 边界以内重新选择。**TOVERIFY：** 系统允许的 AXI3 交织规则需结合集成约束确认。
- 每个方向的 ID 跟踪容量为 4 个已接受地址事务；同周期最多登记或清除一项。跟踪器允许命中任意槽位，不保证严格队首次序。
- 相同 ID 的协议排序仅由 ID 匹配近似约束；RTL 未实现 sequence number 或真正的 reorder buffer。**TOVERIFY：** 不应宣称支持任意乱序完成后重新排序。

## 4. 时钟架构

只有一个时钟域 `AXI_CLK/ACLK/clk`。所有 FIFO、仲裁状态、默认从设备状态和 ID 跟踪状态均在该域。RTL 中没有时钟门控、分频、PLL 或 CDC 结构。目标频率未知，**TOVERIFY**。

## 5. 复位架构

外部 `AXI_RSTn` 为低有效复位。大部分状态使用异步低有效复位；`sid_buffer` 的两个时序块和 `reorder` 使用同步低有效复位。没有复位同步器或复位释放排序逻辑，因此集成环境必须保证相对 `AXI_CLK` 的安全释放，**TOVERIFY**。FIFO 存储阵列不在综合复位中清零，空状态由指针和计数器决定。

## 6. 流水与流控语义

- 每条外部通道采用 ready/valid；边界 FIFO 提供反压。
- 地址进入下游 FIFO前还受 4 项 SID 跟踪容量限制；读返回和写数据离开交叉开关前受 ID 清除/资格逻辑限制。
- 无 flush、kill、取消或超时机制。复位是唯一全局丢弃在途状态的方法。
- FIFO 为空时不组合旁路，数据至少跨一个存储时钟边界；满时即使同拍读取也不接受新写入。

## 7. 存储与排序语义

所有地址为字节地址，传递 `LEN/SIZE/BURST` 而不修改。设计没有数据存储器、缓存或一致性状态，仅包含通道 FIFO和 4 项 ID 数组。每端每通道 FIFO深度为 4；总计 30 个 FIFO。AXI3 的 4 位 `LEN` 支持最多 16 beat 的字段表达。

读/写地址跟踪数组用于限制 outstanding 和筛选返回/写数据，不执行严格重排。不存在跨 ID 的全局顺序保证；同 ID 顺序是否完全满足 AXI3 需协议验证，**TOVERIFY**。

## 8. 配置模型

无运行时寄存器。编译期参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `WIDTH_CID` | 4 | 通道 ID 扩展宽度 |
| `WIDTH_ID` | 4 | 上游 ID 宽度 |
| `WIDTH_AD` | 32 | 地址宽度 |
| `WIDTH_DA` | 32 | 数据宽度 |
| `WIDTH_DS` | `WIDTH_DA/8` | strobe 宽度 |
| `WIDTH_SID` | `WIDTH_CID+WIDTH_ID` | 下游扩展 ID 宽度 |

`axi_crossbar` 另有三个基址/窗口参数，默认如 §2.2；`NUM_MASTER/NUM_SLAVE` 虽存在，但端口、数组、仲裁器和循环大量硬编码为 3，不能视为真正可扩展参数。**TOVERIFY**。

## 9. 性能契约

以下均为结构推断，**TOVERIFY**：

- 无争用、FIFO非空/非满且接收端持续 ready 时，每个独立目标通道理论上可接受 1 beat/cycle。
- 单一目标的 AW/W/AR 各自最多 1 beat/cycle；单一发起端的 B/R 各自最多 1 beat/cycle。
- 每个外部通道可缓冲 4 项；每个读/写 ID 跟踪器最多记录 4 个地址事务。
- 从发起端入口握手到目标端可见，至少经过入口 FIFO写入/读出与出口 FIFO写入/读出，最低延迟依 ready 相位约为数拍，RTL 没有固定端到端周期承诺。
- 默认从设备一次只处理一个读事务和一个写事务；读错误按 `ARLEN+1` 产生多个 beat，写错误等待 W burst 后返回一个 B。

## 10. 错误模型

| 条件 | RTL 行为 |
|---|---|
| AW/AR 地址未命中 | 路由到默认从设备 |
| 默认读 | 每 beat `RRESP=DECERR(2'b11)`、`RDATA=all-ones` |
| 默认写 | 接收 W burst 后 `BRESP=DECERR(2'b11)` |
| 默认写 WLAST 缺失或 AWID/WID 不同 | 仅仿真 `$display`，综合硬件不保护 |
| FIFO 溢出/下溢 | ready/valid 阻止常规访问；无断言 |
| 非法 FSM 状态 | 部分 FSM 无 default 恢复 |
| 非法协议属性/地址重叠/ID 约束 | 无硬件错误输出或断言 |

所有设计模块均无 SVA/OVL assertion。

## 11. 前向进展保证

轮询意图可减少持续竞争下的饥饿，但 `last_winner` 在“存在请求”时更新，并非只在成功握手时更新。外层 grant 锁定能在反压时稳定选择。只要接收端最终 ready、请求保持 valid、ID 跟踪项能释放，事务应继续推进。没有超时、丢失 credit 检测或死锁恢复；因此无法给出有限最坏延迟，**TOVERIFY**。

关键依赖链为：AW 被接受并登记 ID → 对应 W 才有资格通过 → 候选 `WVALID & WLAST` 清除 ID；AR 被接受并登记 ID → 匹配 R 才有资格通过 → 候选 `RVALID & RLAST` 清除 ID。目标端若不产生末 beat，4 项表最终会满并反压新地址；反之，末 beat在输出 FIFO满时可能尚未握手就提前清项。

## 12. 总线协议

信号集合是 AXI3 风格：独立五通道、4 位 `AWLEN/ARLEN`、存在 `WID`，支持最多 16 beat burst。它不是完整的标准 AXI3 端口集合：未提供 `LOCK/CACHE/PROT/QOS` 等属性，并额外依赖定制 ID 编码。故应称“AXI3 子集/风格接口”，完整合规性 **TOVERIFY**。

## 13. 兼容性说明

- 数组端口和未打包数组需要支持相应 Verilog/SystemVerilog 扩展的工具。
- 设计固定为 3 个发起端和 3 个真实目标端；改变数量参数不足以完成扩展。
- `WIDTH_ID=4`、`WIDTH_SID=8`、目标/发起端编码各 2 位被多处位切片和常量隐式假定；宽度参数并非完全通用。
- 默认地址译码假定 4 KiB 对齐，且目标编码从基址位 `[14:13]` 导出。
- `filelist.f` 的 testbench 路径与当前目录布局不一致。

## 14. 风险评估

| 风险 | 影响 | 建议 |
|---|---|---|
| `reorder` 只做任意槽成员匹配 | 文档/验证可能误以为严格保序 | 按“outstanding-ID filter”验证，若需严格顺序则重构 |
| 参数表面可配、实现硬编码 3/4/8 位 | 非默认参数可能编译或功能失败 | 锁定合法参数或系统化参数化 |
| `sid_buffer` 由两个时序块写同一数组 | 综合可移植性、同拍 push/clear 语义有风险 | 合并为单一 next-state 更新 |
| SID clear 未与真实 FIFO ready 握手相与 | 末 beat受反压时可能提前释放 outstanding 项 | clear 条件改为完整 `VALID & READY & LAST` |
| FIFO 满且同拍 pop 时不允许 push | 出现不必要气泡 | 若吞吐要求严格，增加满态并行交换 |
| 混合同步/异步复位且无同步释放 | 亚稳或状态不一致 | 在顶层定义复位同步策略 |
| 无协议断言与参数合法性检查 | 错误集成难以及时发现 | 增加 AXI/ID/地址互斥/FIFO assertions |
| 默认从设备检查仅仿真输出 | 硬件中协议错误静默 | 明确错误上报策略 |
| 返回/写数据逐 beat 重仲裁 | burst 交织可能超出系统预期 | 对照 AXI3 ordering/interleave 规则验证 |
| 地址窗口可能重叠且无检查 | 同一请求可能被多个目标接受 | elaboration assertion 或生成期检查 |
